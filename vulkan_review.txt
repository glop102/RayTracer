Code Review: src_vk_cpp Ray Tracer
====================================

Overall the code is genuinely clean — good RAII discipline, move-only types where it matters,
sensible module boundaries, and clear comments where the Vulkan spec has unintuitive requirements.
The suggestions below are about patterns that will hurt as the scene/material system grows, not
cosmetic complaints.


1. [DONE 89efc60] Shared GLSL hit shader header
------------------------------------------------
Extracted shaders/hit_common.glsl containing all shared declarations
(FloatBuf/UintBuf buffer refs, MeshRef/GpuMaterial/InstanceData structs,
SSBO bindings 2-4, HitResult, bary, and fetch_world_normal()). Both hit
shaders reduced to #include + main(). ShaderIncluder added to
shader_compiler.h to resolve #include relative to the shader directory.


2+3. [DONE c7e9b57] Unified device buffer upload and address helpers
---------------------------------------------------------------------
Added upload_device_buffer() and buffer_device_address() to gpu_buffer.h/cpp.
accel.cpp's static buffer_address() removed; the 36-line hand-rolled staging
block in build_tlas replaced with one upload_device_buffer() call (pipeline
barrier dropped — vkQueueWaitIdle inside end_one_shot is sufficient). mesh.cpp's
static upload_buffer() removed; Mesh now stores GpuBuffer vertex_buf/index_buf
instead of loose buf+alloc pairs; private resolve_addresses() eliminates the
duplicated VkBufferDeviceAddressInfo block at the end of both constructors.


4. [DONE 218ea51] Delete dead Camera UBO code; replace orbit with first-person control
--------------------------------------------------------------------------------------
Camera rewritten as a pure C++ struct with no Vulkan dependency. All UBO/descriptor
infrastructure removed (~60 lines). Orbit state (theta/phi/radius/target) replaced by
FPS state (pos/yaw/pitch). Controls: click to capture mouse, ESC to release; WASD
moves along camera axes; E/Q move world-up/down; mouse drag updates yaw/pitch.
tick(float dt) polls GLFW key state each frame; main.cpp tracks wall-clock dt via
glfwGetTime(). Starting position (0, 0.2, 0.8) looking toward -Z frames the scene.


5. [SUPERSEDED by #4] Camera::rt_push() and Camera::update() both compute eye position
--------------------------------------------------------------------------------------
Both methods and the spherical coordinate duplication were eliminated when the orbit
camera was replaced with the FPS camera (commit 218ea51). rt_push() now derives forward
from yaw/pitch; update() is gone entirely.


6+10. [DONE 77a3d1c] Auto-extract NEE light list from emissive instances
-------------------------------------------------------------------------
Mesh now retains cpu_positions/cpu_indices after GPU upload.
extract_light_triangles() (scene_data.h/cpp) scans all SceneInstances for
non-zero emissive materials and collects world-space triangles automatically.
main.cpp's hand-coded lv0/lv1/lv2/lv3/emit block removed; the GpuMaterial
emissive field is now the single source of truth. All triangles of emissive
meshes are included — back-facing ones return zero via the shader's
cos_theta_l check, which generalises correctly to arbitrary scene geometry.


7+8. [DONE c9d1263] make_stage helper + MISS/HIT_COUNT constants + handle loop
------------------------------------------------------------------------------
make_stage() lambda in rt_pipeline.cpp collapses each 4-line stage block to
one line; stages[] is now a readable list. std::size(stages/groups) replaces
magic 6/5 in pipe_ci. MISS_COUNT=2/HIT_COUNT=2 named constants drive all
offset math and region sizes — updating either requires changing one number.
Five individual memcpy calls replaced by a loop over {raygen,miss,hit}
regions so adding a hit group only touches HIT_COUNT + the groups array.
(Decided against SbtLayout helper struct — named constants + a loop solve
all four coupling points without new infrastructure.)


9. GpuBuffer requires manual lifetime management
-------------------------------------------------
File: gpu_buffer.h:8-12

GpuBuffer is a plain struct — the caller must call destroy_buffer() or it leaks. SceneData handles
this correctly, but any future code that forgets (or throws before reaching the destroy) will leak.
Compare with Mesh and AccelStructure which both carry their own device/allocator and clean up in
their destructors.

The tension is that RtOutput stores std::vector<GpuBuffer> as non-owning references (ssbos_ in
rt_output.h:38 — SceneData owns the memory, RtOutput just reads it). So GpuBuffer can't be made
unconditionally owning without a plan for the borrow case.

One clean option: introduce a GpuBufferRef (just buf + size, no alloc) for the non-owning case,
and make GpuBuffer RAII with a destructor. The RtOutput::ssbos_ member becomes
std::vector<GpuBufferRef>. This separates "I own this memory" from "I have a view into someone
else's memory."


10. Emissive color is defined in two places
--------------------------------------------
File: main.cpp:111 (in materials array), main.cpp:130 (emit variable)

The area light's emission values {4.0f, 3.5f, 2.5f} appear in the GpuMaterial array and again in
the GpuLightTriangle construction. If you change the light intensity in the material, the NEE
samples silently use the old value. A simple named constant at the top of main() would at least
make them share a definition, even before a more principled "scan emissive materials to build
light list" approach.
