Vulkan Ray Tracing Rework Plan
==============================

The current CPU architecture maps almost directly onto Vulkan's ray tracing model.
The goal is to eventually replace the CPU path tracer with a Vulkan RT pipeline,
but Vulkan has enough boilerplate that it's worth building up in stages rather
than attempting a full translation in one shot.


STAGE 1: Basic Vulkan Rasterization Pipeline
---------------------------------------------
Get comfortable with Vulkan before touching RT extensions. A rasterization
pipeline covers all the infrastructure that RT will also need.

Libraries (use all four from day one):
  - vk-bootstrap  : instance/physical device/logical device/swapchain in ~50
                    lines instead of ~400; do not hand-roll these
  - VMA           : replaces vkAllocateMemory + vkBindBufferMemory with one
                    call; RT requires heavy buffer allocation so this pays off
                    immediately in Stage 2
  - GLFW          : window + VkSurfaceKHR creation
  - GLM           : vec3/mat4 math that matches GLSL layout rules; important
                    for correct UBO alignment

Milestones:
  1. [DONE] Instance + device + swapchain + render pass
       vk-bootstrap handles instance/device/swapchain boilerplate. Validation
       layers enabled from the start. RT extension feature structs chained into
       device pNext (all bits FALSE) to confirm GPU support early.
       Semaphore free-list design: image_count+1 acquire semaphores; old
       per-image semaphore recycled on re-acquire. All sync resources
       (cmd bufs, render_finished, in_flight) indexed by swapchain image index,
       not frame-in-flight slot.

  2. [DONE] Draw a triangle (hard-coded vertex shader, pipeline, shaders)
       Positions and colors hard-coded in the vertex shader. Runtime GLSL→SPIR-V
       compilation via libshaderc (no pre-compilation step). Dynamic viewport and
       scissor state (VK_DYNAMIC_STATE_VIEWPORT / SCISSOR) so the pipeline object
       is never recreated on resize. Framebuffer resize support added: GLFW
       callback sets a flag; main loop calls Swapchain::recreate() +
       RenderPass::rebuild_framebuffers() then continues.

  3. [DONE] Load and draw the bunny mesh (vertex buffer, index buffer, depth buffer)
       Parse existing PLY files from bunny/reconstruction/ into CPU-side
       glm::vec3 vertex and uint32_t index arrays. Upload to device-local VkBuffers
       via VMA staging buffers (TRANSFER_SRC CPU → TRANSFER_DST DEVICE_LOCAL).
       Add depth attachment (VK_FORMAT_D32_SFLOAT) to the render pass; depth image
       owned by RenderPass and recreated alongside framebuffers on resize.
       Camera MVP passed as a push constant (mat4, vertex stage). Fragment shader
       computes face normals via dFdx/dFdy on world_pos and maps them to RGB —
       no CPU-side normal computation needed, gives flat-shaded face visualization.
       Note: Stanford bunny PLY uses X-up convention (not Y-up as assumed).

  4. [DONE] Orbit camera with a UBO (uniform buffer object)
       Camera struct owns a persistently-mapped VkBuffer (VMA AUTO +
       HOST_ACCESS_SEQUENTIAL_WRITE + MAPPED), descriptor set layout (binding 0,
       vertex stage), descriptor pool, and set. Orbit state is spherical
       (theta/phi/radius + target); left-drag orbits, scroll zooms with radius
       clamped to [0.05, 2.0]. GLFW callbacks route through a small AppState
       struct stored in the window user pointer alongside the resize flag.
       Pipeline layout uses the camera descriptor set layout; push constant
       removed. Vertex shader reads MVP from UBO at set=0 binding=0.

This is ~1800 lines of setup but you only write it once. Every subsequent stage
reuses the same device/swapchain/command buffer scaffolding.

Things to skip for now (add only when a later stage demands them):
  - Multiple render passes or subpasses
  - Additional descriptor sets beyond the camera UBO
  - Push constants, specialization constants, pipeline cache

Skip validation layers in a hurry, but you will regret it. Enable them from day one.


STAGE 2: Add RT Extensions (KHR_ray_tracing_pipeline)
------------------------------------------------------
Requires: VK_KHR_ray_tracing_pipeline + VK_KHR_acceleration_structure.
Check device support first — any RTX 2000+ or RX 6000+ card has it.

New concepts vs rasterization:
  - BLAS (Bottom-Level Acceleration Structure): one per mesh
    Upload triangle positions as a VkBuffer, call vkCmdBuildAccelerationStructuresKHR.
    Driver builds the BVH internally — no SAH code needed.
  - TLAS (Top-Level Acceleration Structure): one per scene
    Array of VkAccelerationStructureInstanceKHR, each with a 4x3 row-major
    transform and a BLAS reference. This is exactly the Instance model.
  - Shader Binding Table (SBT): maps geometry to shader groups.
    One entry per material type (opaque, glass, emissive, ...).

Milestone: [DONE] shoot a ray from a hard-coded camera, return the barycentric
coordinates of the first hit as a color. No shading, no BVH code, just
confirm the pipeline is wired up.

Key implementation notes:
  - shaderInt64 is a Vulkan 1.0 core feature in VkPhysicalDeviceFeatures, NOT
    VkPhysicalDeviceVulkan12Features. Must enable via VkPhysicalDeviceFeatures2
    in the DeviceBuilder pNext chain (leave pEnabledFeatures NULL).
  - SBT buffer base address must satisfy shaderGroupBaseAlignment (typically 64
    bytes). VMA suballocation may not satisfy this — use vmaCreateBufferWithAlignment.
  - GLM mat4 is column-major; VkTransformMatrixKHR is row-major 3×4. Transpose
    the GLM mat4 and memcpy the first 12 floats to get the right layout.
  - Nix flake builds from git-tracked files only. New files must be `git add`ed
    before `nix build` or they are silently invisible to the build system.


STAGE 3: Translate the Path Tracer
-----------------------------------
[DONE] Full path tracer translation with multi-material scene and glass.

Shader stage mapping (implemented):
  CPU                             GPU (GLSL)
  --------------------------------+------------------------------------------
  Camera::_cast_ray_for_color()  | raygen shader — iterative bounce loop
  BRDMaterial::scatter()         | closest-hit shader (opaque hit group)
  PureTransparentMaterial        | closest-hit + any-hit (glass hit group)
  Skybox::color()                | miss shader
  Triangle intersection          | built-in (no intersection shader needed)
  TriangleBVH8                   | BLAS (driver-managed)
  BVH8List / Instance            | TLAS + instance transforms

Bounce loop: chose option (a) — iterative traceRayEXT() loop in raygen (10
bounces max), Russian roulette termination after bounce 3. Not recursive —
maxPipelineRayRecursionDepth = 1.

RNG: PCG32 seeded per pixel per frame: seed = (y*width + x) ^ (frame * prime),
two warm-up steps. All random samples drawn inline from one state uint.

Accumulation: RGBA32F storage image, running mean via mix(prev, new, 1/(n+1)).
Blit to B8G8R8A8_SRGB swapchain image — Vulkan applies sRGB gamma on blit.
frame_index resets to 0 on camera move or window resize.

Vertex buffer layout: interleaved {x,y,z, nx,ny,nz} — 6 floats (24 bytes) per
vertex. BLAS geometry reads only positions (vertexStride=24); closest-hit shader
reads normals at offset +3 via GL_EXT_buffer_reference device address access.

Smooth normals: area-weighted accumulation (cross product magnitude = 2×area),
then normalize. Smoother than angle-weighted for meshes with variable triangle
sizes. Barycentric interpolation in the closest-hit shader.

Multi-material/multi-instance scene:
  - SceneData owns three SSBOs: mesh_refs (vertex+index addresses), materials
    (diffuse/specular/emissive/roughness/ior), instances (mesh_idx + mat_idx).
  - gl_InstanceCustomIndexEXT indexes into instances[], which fans out to the
    correct mesh ref and material for that TLAS instance.

Glass (second SBT hit group, sbt_record_offset = 1):
  - BLAS built without VK_GEOMETRY_OPAQUE_BIT_KHR so any-hit can fire.
  - glass_closest_hit.rchit: same vertex/normal lookup; stores outward-facing
    normal (no back-face flip); sets payload.ior = +mat.ior (entering) or
    -mat.ior (exiting) based on gl_HitKindEXT.
  - glass_any_hit.rahit: calls ignoreIntersectionEXT (a statement, not a
    function — no parentheses) when ray has SkipClosestHitShader flag, making
    glass transparent to future shadow rays.
  - raygen traces with flags=0u (per-BLAS opacity respected) rather than
    gl_RayFlagsOpaqueEXT so the any-hit shader can fire for glass geometry.
  - Glass scatter in raygen: Schlick Fresnel + GLSL refract() builtin, with
    TIR detected by dot(refracted, refracted) < 0.001 → fallback to reflect.
  - Box mesh: 24 vertices (4 per face, face normals), 36 indices, CCW winding
    verified outward with cross-product check at construction time.


STAGE 4: Rendering Quality
--------------------------
The path tracer is correct but slow to converge. These improvements are roughly
ordered by noise-reduction-per-effort.

  1. Emissive materials + Next Event Estimation (NEE)
     Currently the only light source is the sky. NEE adds a direct-lighting
     sample at every bounce: trace a shadow ray toward a randomly chosen light,
     weight by solid angle, add to the estimate without waiting for a path to
     accidentally hit it. Variance drops dramatically for scenes with small
     lights. Requires:
       - emissive field already in GpuMaterial (used now only for sky miss)
       - shadow ray: traceRayEXT with gl_RayFlagsSkipClosestHitShaderEXT |
         gl_RayFlagsTerminateOnFirstHitEXT; miss = light visible
       - glass any-hit already wired to pass shadow rays through (ignoreIntersectionEXT)
       - a light list SSBO so the raygen can sample a random emissive triangle
     MIS (Multiple Importance Sampling) balances NEE and BRDF samples to handle
     both large and small lights well; add it after NEE is working.

  2. GGX microfacet BRDF
     The current scatter is a linear blend between mirror-reflect and cosine-
     hemisphere. Real specular lobes follow the GGX (Trowbridge-Reitz) normal
     distribution — sharper highlights, correct energy conservation, plausible
     look for metals and dielectrics. Replace the mix() scatter with:
       - sample a GGX half-vector H given roughness α = roughness²
       - reflect ray_dir about H to get scatter direction
       - weight throughput by the full Cook-Torrance term (D·G·F / 4·NdotL·NdotV)
     The math is ~30 lines of GLSL but must be derived carefully; pbrt-v4 chapter
     9 is the reference.

  3. Beer–Lambert absorption for glass
     One-line change in the glass refraction path:
       throughput *= exp(-absorption_color * gl_HitTEXT);
     Add absorption_color to GpuMaterial (reuse _pad1). Gives colored glass and
     makes thick vs thin glass visually distinct.

  4. Textures
     Bind a VkImageView array (VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER with
     variable descriptor count) to the descriptor set. Add texture_index fields
     to GpuMaterial for diffuse/roughness/normal maps. The closest-hit shader
     reads UV coordinates from the vertex buffer (extend stride from 6 to 8
     floats: add u, v) and samples the appropriate texture. Normal maps require
     a TBN matrix from tangent/bitangent computed from UVs.

  5. GLTF scene loading
     Replace the hard-coded bunny + box with a GLTF 2.0 loader (tinygltf is
     header-only). Each GLTF mesh becomes a BLAS; each node becomes a TLAS
     instance with the node's world transform. Material properties map directly
     to GpuMaterial fields. This is mostly plumbing but unlocks arbitrary scenes.


ARCHITECTURE THAT CARRIES OVER UNCHANGED
-----------------------------------------
  - SAH BVH construction: irrelevant — driver builds it from triangle data.
  - SoALeaf / moller_trumbore_8 / aabb_test_8: irrelevant — RT cores do this.
  - The overall path tracing algorithm: direct translation.
  - BBox, camera math, skybox colors: rewrite in GLSL/GLM but logic identical.
  - PLY loader: still runs on CPU, uploads vertex/index buffers to GPU.

The Instance transform is the cleanest win: what took manual rot/rot_inv matrix
math in C++ becomes a single field in VkAccelerationStructureInstanceKHR.


ROUGH EFFORT ESTIMATE
---------------------
  Stage 1 (rasterization foundation)  : 1-2 weeks
  Stage 2 (RT pipeline + first ray)   : 3-5 days
  Stage 3 (full path tracer)          : 1-2 weeks

Total: 3-5 weeks for a faithful translation. The algorithmic work is
small — most time goes to Vulkan API plumbing and shader debugging.

Expected performance vs current CPU implementation (4:25 / frame at 4K, 1000spp):
  A mid-range RT-capable GPU (RTX 3070 class) would likely do the same frame
  in 10-30 seconds. High-end (RTX 4080+): potentially under 10 seconds.
  Wavefront path tracing and denoising (DLSS or OIDN) could push interactive
  framerates for lower spp counts.
